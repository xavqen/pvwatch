# PVwatch — Complete Free-Tier Video Platform

## What is included
- Public home page, library and watch page
- Private creator dashboard + password login
- Separate upload page
- Direct browser upload to Supabase Storage using signed upload URLs
- Upload progress
- Video metadata stored in Supabase Postgres
- Automatic thumbnail frame selector: choose any point in the local video and capture a JPEG cover
- 6 quick frame positions + custom timeline
- Optional WebVTT subtitle upload
- Admin delete
- Views counter
- Responsive player: play/pause, seek, +/-10 sec, mute, volume, speed, PiP, fullscreen, loop, theater mode, subtitles
- CSP configured for Supabase domains and `blob:` media so browser uploads/video previews are not blocked
- No video files saved on Render's filesystem

## Important free-tier limits
Supabase Free currently allows 1 GB file storage and a maximum 50 MB file size. This project enforces 50 MB per uploaded asset (video/thumbnail/subtitle). For GB-sized long videos, upgrade the storage plan or move to a provider supporting larger multipart/resumable uploads.

## 1) Supabase setup
1. Create a Supabase project.
2. In Storage, create a bucket named `pvwatch` and keep it PRIVATE.
3. Open SQL Editor and run `supabase.sql`.
4. Settings -> API: copy Project URL and the `service_role` secret. Keep service_role server-only.

Signed upload URLs let the server authorize an upload without exposing the service-role key to the browser. Signed read URLs are also generated by the server for private files.

## 2) Local Windows setup
```powershell
cd D:\PVwatch
npm install
copy .env.example .env
```
Edit `.env`:
```env
PORT=3000
SUPABASE_URL=https://YOUR_PROJECT.supabase.co
SUPABASE_SERVICE_ROLE_KEY=YOUR_SERVICE_ROLE_KEY
SUPABASE_BUCKET=pvwatch
ADMIN_PASSWORD=your-strong-password
SESSION_SECRET=make-this-a-long-random-secret
```
Start:
```powershell
npm start
```
Open:
- http://localhost:3000/
- http://localhost:3000/login
- http://localhost:3000/dashboard
- http://localhost:3000/upload
- http://localhost:3000/library

## 4) Render deployment
Render -> New -> Web Service -> select the GitHub repo.
- Build command: `npm install`
- Start command: `npm start`
- Health check path: `/api/health`
- Plan: Free

Add these Environment Variables in Render:
- `SUPABASE_URL`
- `SUPABASE_SERVICE_ROLE_KEY`
- `SUPABASE_BUCKET=pvwatch`
- `ADMIN_PASSWORD`
- `SESSION_SECRET`
- `NODE_ENV=production`

Render web services are appropriate for Express and expose an `onrender.com` URL. Render Free instances can spin down after inactivity and their filesystem is ephemeral, so PVwatch intentionally stores media in Supabase instead of local disk.

## 5) Why quality is not 360p/720p yet
This version uploads one original source. A real multi-quality selector requires creating extra 360p/480p/720p/1080p encodes (normally with FFmpeg) and switching between those files or HLS/DASH manifests. The UI already contains the quality setting area and clearly reports `Original` until variants exist.

## 6) Security notes
- Never put `SUPABASE_SERVICE_ROLE_KEY` in frontend JS.
- Keep the `pvwatch` bucket private.
- Change `ADMIN_PASSWORD` and `SESSION_SECRET` before deployment.
- Replace simple password login with Supabase Auth before a public multi-admin production launch.

## 7) Free hosting reality
Render's Free web service can sleep, and its local filesystem is not persistent. Supabase Free currently gives 1 GB file storage, 5 GB cached egress, 5 GB uncached egress and a 50 MB file limit. This is fine for a small MVP, but not for a large public video platform.
